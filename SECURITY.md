## Что проверено и почему это не проблема

**1. Ключи и пароли.** В коде секретов нет. `ANTHROPIC_API_KEY` и `AIRL_ADMIN_TOKEN`
объявлены через `defineSecret(...)` (Google Secret Manager) в `functions/index.js` — это
правильный паттерн, значения нигде не хранятся в репозитории. Файлы новые, ещё не
закоммичены — утечки в историю git нет.

Единственный ключ, который виден в браузере — `AIzaSyDNS...` (Firebase Web API key) в
`diagnostics.html` и в атрибуте `data-key` у `airl-lead.js`. Это не секрет в обычном
смысле: он и раньше был публичным в `firebase-bridge.js` этого же проекта. Защита идёт
не через секретность ключа, а через правила Firestore (ниже) и, отдельно, через
ограничение по домену в Google Cloud Console — оно пока не проверено (см. «Что сделать
руками»).

**2. Доступ к данным.**
- Все четыре функции (`group`, `diagnostics`, `lesson1`, `closeGroup`) проверяют заголовок
  `x-airl-token` на сервере (`guard()` в `functions/index.js`), сравнивая с настоящим
  значением секрета — не сравнением на клиенте. Пароль в `admin.html` не хардкожен: форма
  реально стучится в функцию и получает 401, если пароль неверный. `sessionStorage`
  используется только чтобы не вводить пароль на каждый клик — это нормально для панели
  на 1–2 человек, не постоянная сессия.
- Правила Firestore проверены построчно после ручного слияния: старые блоки `requests` и
  `tasks` не тронуты, новые (`leads`, `groups_public`, `groups`+`responses`) добавлены
  внутрь того же `match /databases/{database}/documents`, catch-all `match /{document=**}`
  (запрет всего остального) остался последним и продолжает действовать. Скобки сбалансированы.
- `groups/{code}` целиком закрыт (`allow read, write: if false`) — только Cloud Functions
  с Admin SDK видят данные группы и ответы сотрудников. Вложенная `responses` разрешает
  `create` только если код группы существует и активен, и требует все обязательные поля
  анкеты — это тоже серверная проверка (Firestore применяет `firestore.rules` независимо
  от того, идёт запись через SDK или через голый REST, как в `diagnostics.html`).
- `groups_public/{code}` отдаёт наружу только `company` и `active` — ни один личный
  ответ сотрудника через неё не виден.
- Файлы отчётов (Excel, презентация) отдаются подписанными ссылками на 30 дней
  (`getSignedUrl`, проверено в `agents/diagnostics.js` и `agents/lesson1.js`) — правила
  Storage в этом репозитории вообще не участвуют, доступ идёт только через подпись,
  сгенерированную сервером.

**3. Вводимые данные.** Firestore-правила проверяют длину и тип полей на сервере
(`leads`, `responses`) — это не только проверка в браузере. Cloud Functions валидируют
код группы и содержимое запроса до вызова модели.

**4. Логи.** Единственный `console.error` (в `fail()`, `functions/index.js`) печатает
объект ошибки — это стандартная практика, специальных полей с паролями или токенами
в логи не выводится.

## Что сделать руками (не могу сделать сам)

### 1. Задать секреты перед деплоем функций
Зачем: без них функции не задеплоятся, а пароль/ключ никогда не должны появляться в
переписке или в коде.

```
firebase functions:secrets:set ANTHROPIC_API_KEY
firebase functions:secrets:set AIRL_ADMIN_TOKEN
```

Выполните это в своём терминале (не через меня) — так значения не попадут ни в один чат
или лог. Для `AIRL_ADMIN_TOKEN` придумайте длинную случайную строку — это единственная
защита `/admin.html`.

### 2. Ограничить Web API key по домену
Зачем: ключ публичный по природе, но без ограничения им можно достучаться до вашего
Firestore REST API с любого сайта (сами данные всё равно защищены правилами, но домен
экономит от чужого фонового шума и спама).

1. [Google Cloud Console → API Credentials](https://console.cloud.google.com/apis/credentials?project=landing-page-8e314)
2. Откройте ключ `AIzaSyDNS...` (Browser key)
3. Application restrictions → HTTP referrers → добавьте `https://airl.kz/*` и `https://www.airl.kz/*`
4. Проверка: с другого домена запрос к Firestore REST с этим ключом должен вернуть ошибку

### 3. Потолок расходов на Anthropic
Зачем: агент вызывает модель на каждое нажатие «Собрать портрет» / «Собрать урок» —
без лимита всплеск использования не остановится сам.

1. [console.anthropic.com](https://console.anthropic.com) → Settings → Limits
2. Задайте месячный лимit (README пакета оценивает один прогон агента 1 в 30–60 тыс.
   токенов на вход, до 16 тыс. на выход — ориентируйтесь на ожидаемое число групп в месяц)
3. Проверка: лимит должен отображаться в разделе Limits как активный
